# Правила проекта

## Что это

Локальный тренажёр английских слов (аналог Quizlet): `index.html` открывается
двойным кликом, без сервера и сборки. Слова лежат в `words.js` модулями —
у каждого модуля свой независимый прогресс. Подробности — в `README.md`.

## Главное правило: коммит и пуш после каждого изменения

**После каждого законченного изменения сразу делать коммит и `git push`.**
Не ждать отдельной просьбы, не копить правки в рабочей копии.

Порядок действий:

1. Внести изменение и проверить его (см. «Проверка перед коммитом»).
2. `git add` затронутых файлов — только их, без «мусорных».
3. Коммит с понятным сообщением (формат — ниже).
4. `git push origin main` — сразу, в том же шаге.
5. В ответе пользователю написать, что запушено.

Одна задача = один коммит. Если правок несколько и они про разное —
несколько коммитов, но каждый всё равно пушится сразу.

Если push не проходит (нет сети, отозван доступ) — не откатывать коммит,
а сказать об этом пользователю и оставить коммит локально.

## Сообщения коммитов

* **По-английски**, коротко и осмысленно: что изменилось, а не «update files».
* Первая строка — до ~60 символов, повелительное наклонение: `Add`, `Fix`,
  `Make`, `Remove`.
* Тело добавлять только если из первой строки непонятно «зачем».
* В конце каждого коммита:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

Примеры хороших сообщений:

```
Require exact spelling in typed answers
Keep answer panel open until user clicks next
Give each word set its own module and progress
```

## Проверка перед коммитом

Быстрые проверки, которые должны проходить:

```bash
node --check app.js
node -e 'global.window={};require("./words.js");const S=window.WORD_SETS;console.log("модулей:",S.length,"| слов:",S.reduce((n,m)=>n+m.words.length,0))'
python3 -c "import ast; ast.parse(open('tools/pdf_to_words.py',encoding='utf-8').read())"
```

Если менялось поведение приложения — проверить его в браузере, а не только
синтаксис. Приложение открывается по `file://`, поэтому нельзя использовать
`fetch()` для локальных файлов: данные подключаются через `<script src>`.

## Что не коммитить

* `.DS_Store` и прочий мусор macOS — он в `.gitignore`.
* Временные файлы проверок: держать их в каталоге-черновике, а не в папке проекта.

## Правила самого приложения

Их нельзя ослаблять «для удобства» — это осознанные решения:

* **Написание проверяется точно.** Опечатка в один символ даёт вердикт `near`:
  ответ не засчитывается, приложение просит переписать. Второе допустимое
  написание (`analyze` / `analyse`, `labor` / `labour`) задаётся только полем
  `accept` у слова — приложение не придумывает такие пары само и не сворачивает
  буквы «по похожести».
* **Артикль и частица `to` не важны**: `the access`, `to access` и `access` —
  одно и то же. Это снимается в `norm()`; добавлять туда новые «поблажки»
  (например, игнорировать окончание `-s`) нельзя.
* **Разбор ответа не исчезает сам** — ни при верном ответе, ни при неверном.
  Переход дальше только по кнопке «Дальше» или `Enter`.
* **Озвучка переключается**: `speak()` на повторный вызов с тем же текстом
  останавливает чтение и возвращает `false`. Кнопки, которые меняют надпись
  на «Остановить», опираются на это возвращаемое значение и на колбэк `onEnd`.
* **Голос английский**, предпочтительно американский (`pickVoice()`).

## Чтение

Тексты и словарь подсказок — в `texts.js`, раздел не должен зависеть от
модулей со словами и от прогресса по ним. Тексты пишутся специально для
тренажёра: **не копировать чужие тексты** с сайтов и из учебников, это
чужая интеллектуальная собственность. После правки текстов проверять, что
каждая словоформа есть в `gloss` — иначе при наведении не будет перевода:

```bash
node -e 'global.window={};require("./texts.js");const R=window.READING;const P=/[A-Za-z]+(?:['"'"'’-][A-Za-z]+)*/g;const m=new Set();R.texts.forEach(t=>t.s.forEach(([d])=>(d.match(P)||[]).forEach(w=>{if(!R.gloss[w.toLowerCase()])m.add(w)})));console.log(m.size?[...m]:"все слова покрыты")'
```

Начальная форма в `gloss` пишется в скобках — `"authorities": "власти (authority)"`.
Из неё `cardDraft()` собирает карточку по кнопке «＋ в словарь», поэтому
в скобках должно стоять одно английское слово, а не пояснение по-русски.

## Модули из браузера

Кроме модулей из `words.js` есть «свои» — они лежат в `localStorage`
(`S.userSets`) и собираются прямо в приложении: кнопкой «＋ в словарь» из
текста для чтения или на экране «Добавить слова». Слова, дописанные к модулю
**из файла**, лежат в `S.extra[<id модуля>]` и подмешиваются к нему в
`rebuildModules()`; добавлять их только через `addWordToModule()`.

Приложение не умеет писать в `words.js` (оно открывается по `file://`), но
пользователь не должен копировать код руками: добавление всегда происходит
сразу, а выгрузка в файл — это добровольная кнопка в настройках, а не шаг
в сценарии добавления. Всё, что строится по модулям, собирается функцией
`rebuildModules()` — её нужно вызывать после любого изменения `S.userSets`,
иначе `WORDS` и `BY_KEY` останутся старыми.

Убрать добавленное слово можно крестиком в списке (`isAddedWord()` /
`removeAddedWord()`); слова из `words.js` не трогаются.

Часть речи новому слову ставит `guessPos()` — по ней работают фильтры
в списке слов и подбор вариантов в тесте. Для английского она угадывается
только по концовке слова и часто ошибается, поэтому на экране добавления
есть выбор руками, а константой `pos` проставлять нельзя.

Транскрипция для новых слов считается в `autoTr()` — это порт правил из
`tools/pdf_to_words.py`. Для английского она заведомо приблизительная
(ударение всегда на первом гласном), поэтому результат обязательно
показывается пользователю на правку и сам по себе в словарь не попадает.
Правишь правила в одном месте — поправь и во втором.

На экране «Добавить слова» строка выглядит как **`source = источник`**:
слово слева, перевод справа, всё после `|` — необязательное (транскрипция,
множественное число и его транскрипция). Черновая транскрипция показывается
в предпросмотре `renderAddPreview()` отдельным полем и правится там же;
правки живут в `addTrEdits` по ключу «слово|перевод», чтобы переживать
перерисовку. Предпросмотр — не лишний шаг, а то самое «показать на правку»:
убирать его нельзя, иначе автотранскрипция попадёт в словарь незамеченной.

Отметки в карточках лежат в `S.cards[<id модуля>]` вместе с порядком колоды
и позицией; пишутся через `saveCards()`, чистятся через `clearCards(id)`.

## Правки в словаре

`words.js` — пользовательские данные. Не переписывать модули целиком и не
менять `id` существующих модулей: к `id` привязан прогресс в браузере.
Новая партия слов = новый модуль в конце списка.
